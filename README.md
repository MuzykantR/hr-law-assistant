# Ассистент по Трудовому кодексу РФ (RAG)

Отвечает на вопросы сотрудников о трудовых правах — отпуск, увольнение, командировки, зарплата —
**только по тексту Трудового кодекса** и ссылается на конкретную статью и часть.

Основан на кейсе хакатона «AI-импульс 2.0» (корпоративный AI-помощник по внутренним регламентам).
Вместо закрытых регламентов компании используется открытый текст ТК РФ: структура у них одинаковая
(статья → часть → пункт), а данные можно хранить в репозитории.

```
$ uv run python ask.py "Можно ли разбить отпуск на несколько кусков?"
Да, ежегодный оплачиваемый отпуск можно разделить на части [ст. 125, ч. 1–3].

Для этого должны быть соблюдены следующие условия:
* Разделение происходит по соглашению между работником и работодателем [ст. 125, ч. 1–3].
* Хотя бы одна из частей отпуска должна быть не менее 14 календарных дней [ст. 125, ч. 1–3].

$ uv run python ask.py "Как приготовить борщ?"
В Трудовом кодексе я не нашёл ответа на этот вопрос.
```

## Как это работает

```
вопрос ──► исправление раскладки и опечаток ──► эмбеддинг ──► косинусная близость к 870 фрагментам ──► top-6
       ──► близость ниже порога? → отказ без вызова модели
       ──► иначе Gemini ──► ответ со ссылками [ст. N, ч. M]
(альтернативы поиска для сравнения: BM25 и гибрид BM25 + эмбеддинги через RRF)
```

0. **Исправление запроса.**
   - *Раскладка* (`rag/layout.py`). Запрос, набранный на английской раскладке («vj;yj kb hfp,bnm jngecr»),
     переводится в русский по словам: слово переводится, если его русская версия есть в словаре кодекса,
     содержит клавиши-буквы (`;` → «ж», `,` → «б») или типичные для такого набора сочетания букв. Если так
     переведена бо́льшая часть слов запроса, переводятся и остальные (`d` → «в», `pfhgkfne` → «зарплату»).
     Латиница, которая должна остаться латиницей (HR, Excel), не трогается.
   - *Опечатки* (`rag/spelling.py`). Исправляются только слова, которых нет в русском языке (проверка по
     словарю OpenCorpora через `pymorphy3`): «положено» и «зарплату» не встречаются в кодексе в такой форме,
     но это правильные слова, их трогать нельзя. Кандидаты — слова на расстоянии одной правки (лишняя,
     пропущенная, заменённая или переставленная буква), предпочтение — словоформам самого кодекса.
1. **Корпус** — 534 действующие статьи ТК РФ (`data/labor_code.jsonl`), скачаны скриптом
   `scripts/download_labor_code.py`. Официальные тексты законов не охраняются авторским правом
   (ГК РФ, ст. 1259, п. 6).
2. **Чанкинг по структуре документа** (`rag/corpus.py`). Кодекс режется не окнами по N символов, а по
   статьям и частям: каждый фрагмент знает, какую статью и какие части он покрывает. Поэтому модель
   может сослаться на «ст. 81, ч. 1», а не на «документ целиком». Пункты-перечисления
   («1) ликвидации организации…») приклеиваются к своей части, длинные статьи делятся по границам частей.
3. **Лексический поиск — BM25** (`rag/retrieval.py`, `rag/text.py`). Ищет по совпадению слов, учитывая,
   насколько слово редкое. Перед поиском слова приводятся к основе стеммером: «отпуска», «отпуском» →
   «отпуск». Силён на точных юридических терминах, но не видит синонимов.
4. **Векторный поиск — эмбеддинги** `gemini-embedding-2`. Вопрос и фрагменты переводятся в векторы,
   близость считается косинусом. Находит перефразировки: «сколько отдыхать в году» ↔ «ежегодный отпуск».
5. **Гибрид — Reciprocal Rank Fusion**: `score = Σ 1 / (60 + rank)` по обоим спискам. RRF смотрит только
   на места в выдаче, поэтому не нужно приводить оценки BM25 и косинусы к одной шкале.
6. **Генерация** (`rag/assistant.py`) — Gemini API напрямую (или те же модели через OpenRouter). Промпт
   разрешает отвечать только по найденным фрагментам, требует ссылку после каждого утверждения и
   фиксированную фразу-отказ, если ответа во фрагментах нет.
7. **Отказ до вызова модели** (`rag/assistant.py`). Если даже самый похожий фрагмент кодекса слабо похож на
   вопрос (косинусная близость ниже порога 0.629), вопрос не про трудовое право: ассистент отказывает сразу,
   не тратя запрос к LLM и не давая ей шанса «додумать» ответ. Порог подобран на данных, см. ниже.
8. **Устойчивость к лимитам** (`rag/llm.py`). На бесплатном тарифе Gemini у каждой модели свой дневной
   лимит, а новые модели бывают перегружены (HTTP 503) или медленны. При ошибке или таймауте ассистент
   переключается на запасную модель, короткие поминутные лимиты эмбеддингов (HTTP 429 «retry in 40s»)
   пережидает, а эмбеддинги уже встречавшихся вопросов берёт из кеша на диске.

## Оценка качества поиска

`data/eval_questions.jsonl` — 111 вопросов, для каждого заранее известна правильная статья, так что метрика
объективна и не требует ручной оценки ответов. Четыре типа вопросов, потому что они проверяют разные части системы:

- **paraphrase** (42) — как спросил бы сотрудник: «можно ли разбить отпуск на куски?»;
- **terms** (15) — короткие запросы словами самого закона: «оплата сверхурочной работы»;
- **layout** (12) — вопросы paraphrase, набранные на английской раскладке;
- **typo** (42) — вопросы paraphrase с опечатками: «мжоно ли разбить отупск на нескалько кусков?».

`layout` и `typo` генерируются из `paraphrase` скриптом `scripts/make_eval_variants.py` с фиксированным
зерном случайности, так что набор воспроизводим.

Сравнение методов поиска — на 57 вопросах paraphrase + terms:

Попадание — фрагмент правильной статьи в первых k результатах. **Recall@k** — доля вопросов с попаданием,
**MRR@10** — среднее 1/место первой правильной статьи (награждает за то, что она именно первая).

| Поиск | Recall@1 | Recall@5 | MRR@10 | Задержка поиска |
|---|---|---|---|---|
| BM25 | 0.39 | 0.68 | 0.50 | 1 мс |
| **Векторный (эмбеддинги)** | **0.88** | **1.00** | **0.93** | 310 мс |
| Гибрид BM25 + векторный (RRF) | 0.58 | 0.89 | 0.72 | 330 мс |

Разбивка по типам вопросов — в [`results/retrieval_eval.md`](results/retrieval_eval.md).
Задержка векторного поиска — это в основном сетевой запрос за эмбеддингом вопроса.

**Результат:** гибрид хуже чистого векторного поиска. На разговорных вопросах BM25 находит мало
(Recall@5 = 0.64), потому что слова сотрудника не совпадают со словами закона. RRF с равными весами
даёт этой выдаче столько же веса, сколько векторной, и правильная статья опускается ниже. На запросах
терминами закона векторный поиск тоже не хуже (Recall@5 1.00 против 0.80 у BM25). Поэтому по умолчанию
используется векторный поиск, а гибрид оставлен как опция. Гибрид полезен, когда в запросах много
точных идентификаторов (номера, коды, артикулы), которые эмбеддинги различают плохо.

### Исправление раскладки

12 вопросов в неверной раскладке, Recall@5:

| Поиск | Без исправления | С исправлением |
|---|---|---|
| BM25 | 0.00 | 0.58 |
| **Векторный** | 0.17 | **1.00** |
| Гибрид | 0.17 | 1.00 |

Без исправления запрос — набор латинских букв: BM25 не находит ни одного совпадения, эмбеддинг почти
не несёт смысла. Все 12 запросов восстанавливаются в исходный русский текст слово в слово.

### Исправление опечаток

42 вопроса с опечатками, Recall@5:

| Поиск | Без исправления | С исправлением | Те же вопросы без опечаток |
|---|---|---|---|
| BM25 | 0.40 | **0.62** | 0.64 |
| Векторный | 1.00 | 1.00 | 1.00 |
| Гибрид | 0.83 | 0.88 | 0.86 |

Исправление почти полностью возвращает BM25 потерянное из-за опечаток: искажённое слово не совпадает со
словами закона. Векторному поиску оно почти не нужно — эмбеддинги устойчивы к опечаткам сами по себе
(MRR растёт лишь с 0.92 до 0.94). Ни один из 57 вопросов без опечаток исправление не изменило.

### Отказ на вопросы не по теме

`data/offtopic_questions.jsonl` — 24 вопроса, на которые в кодексе нет ответа: 12 совсем не по теме
(«как приготовить борщ?») и 12 рядом с темой — бытовые юридические вопросы из других законов
(ипотека, ОСАГО, налоговый вычет). Порог подбирается скриптом `scripts/calibrate_gate.py` на половине
вопросов (калибровочной) и проверяется на второй (отложенной), которую подбор не видел:

| Выборка | Вопросы по кодексу: ответил | Совсем не по теме: отказ | Рядом с темой: отказ |
|---|---|---|---|
| калибровочная | 35/35 | 6/6 | 6/6 |
| отложенная | 34/34 | 6/6 | 6/6 |

Близость лучшего фрагмента у вопросов по кодексу — от 0.665 до 0.778, у вопросов не по теме — от 0.477
до 0.593. Порог 0.629 стоит посередине этого зазора. Выборки маленькие, поэтому зазор в 0.07 — это
наблюдение, а не гарантия: если вопрос по кодексу окажется ниже порога, модель так и не будет вызвана.

### Вопросы-ловушки

`data/trap_questions.jsonl` — 8 вопросов по теме, но с ложной предпосылкой («какая компенсация положена за
работу в полнолуние?»). Порог близости их пропускает, отказать должна сама модель, не подыгрывая
вопросу. `scripts/check_traps.py` сохраняет ответы для ручной проверки. Прогон отложен: бесплатный
дневной лимит Gemini на генерацию (20 запросов на модель) закончился во время разработки.

## Запуск

Нужны Python 3.11+, [uv](https://docs.astral.sh/uv/) и бесплатный ключ
[Gemini API](https://aistudio.google.com/apikey) (или ключ [OpenRouter](https://openrouter.ai/keys)).

```bash
uv sync
copy .env.example .env                # Windows; на Linux/macOS: cp. Вписать GEMINI_API_KEY
uv run python ask.py "Сколько дней отпуска мне положено?"
uv run streamlit run app.py           # веб-интерфейс на http://localhost:8501
uv run python scripts/evaluate.py     # сравнение методов поиска
uv run python scripts/calibrate_gate.py  # подбор порога отказа
uv run python scripts/check_traps.py  # ответы на вопросы-ловушки
uv run pytest                         # офлайн-тесты, ключ не нужен
```

При первом запуске эмбеддинги всех 870 фрагментов считаются один раз (на бесплатном тарифе ~10 минут
из-за лимита 100 запросов в минуту) и кешируются в `data/cache/`.

## Структура

```
rag/corpus.py      загрузка кодекса и чанкинг по статьям и частям
rag/layout.py      исправление раскладки клавиатуры в запросе
rag/spelling.py    исправление опечаток в запросе
rag/text.py        токенизация и стемминг для BM25
rag/retrieval.py   BM25, векторный поиск, гибрид (RRF), кеш эмбеддингов фрагментов и вопросов
rag/llm.py         Gemini (чат и эмбеддинги), запасные модели, лимиты — единственное место, зависящее от провайдера
rag/assistant.py   исправление запроса, порог отказа, промпт, ответ со ссылками
ask.py / app.py    CLI и веб-интерфейс (Streamlit)
scripts/           скачивание кодекса, генерация вариантов вопросов, оценка поиска, подбор порога, ловушки
```

## Откуда идеи

Проекту предшествовал прототип для отбора на хакатон: поиск по научным статьям Норникеля, где
гипотезы проверялись отдельными экспериментами. Часть из них проверена здесь заново на другом корпусе:

| Идея из прототипа | Здесь |
|---|---|
| Стемминг для лексического поиска | `rag/text.py` |
| Гибрид лексического и векторного поиска лучше каждого по отдельности | проверено и **не подтвердилось** |
| Чанкинг по границам норм, название раздела в тексте фрагмента | `rag/corpus.py` |
| Исправление раскладки (эксперимент EXP-004) | `rag/layout.py`, Recall@5 0.17 → 1.00 |
| Исправление опечаток (EXP-001/003) | `rag/spelling.py`, помогает BM25, векторному почти не нужно |
| Порог честного отказа (EXP-006, в прототипе не доведён) | `rag/assistant.py`, порог подобран и проверен на отложенной выборке |

## Ограничения и что дальше

- Тестовый набор небольшой — разница между методами в пару вопросов статистически ненадёжна.
- На бесплатном тарифе Gemini ответ генерируется 10–30 секунд, а дневной лимит — 20 запросов на модель.
- Не юридическая консультация: кодекс не покрывает подзаконные акты и судебную практику.
- Следующие шаги: реранкер (cross-encoder) поверх векторного поиска, автоматическая проверка, что каждая
  ссылка в ответе действительно есть среди найденных фрагментов, добавление других НПА.
